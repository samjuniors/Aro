# Docs governance: reconcile, supersede, archive

Goal: a new session finds one true answer per topic in one place, and old answers are
visibly retired instead of silently contradicting new ones.

## Statuses
| Status | Meaning | Marking |
| --- | --- | --- |
| ACTIVE | The current source of truth for its topic | none |
| GENERATED | Produced by a tool; edit the source, not this | header line `Generated by <cmd>` |
| SUPERSEDED | Replaced; keep only until the replacement is accepted | first line `> SUPERSEDED by <path> on <YYYY-MM-DD>` |
| ARCHIVED | Historical; moved, never edited again | `git mv` to `docs/archive/<area>/` |
| DELETED | Exact duplicate or junk; recoverable from git | `git rm`, listed in the gate report |

## Rules
1. One ACTIVE doc per topic. If two overlap, merge into one, supersede the other.
2. Reconcile means: compare the doc to the code (grep, run, open). Numbers, file paths,
   and commands in a doc must be re-verified before the doc stays ACTIVE. Record the date
   in `DOCS-REGISTRY.md` (`verified` column).
3. Never delete without the founder approving the list at a gate. Prefer ARCHIVED to DELETED
   unless the file is a byte-identical duplicate (`cmp -s`).
4. Archive with `git mv` so history follows. Do not rewrite archived files.
5. Reports (audits, phase reports) are point-in-time: ARCHIVE them when the next phase starts,
   after copying any still-true open items into the live backlog.
6. Decisions live in ADRs (`docs/adr/`, template `0000-template.md`); `DECISIONS.md` is only an index.
   Research notes live in `docs/research/NN-<topic>.md`.
7. Every doc a phase creates or changes is added to `DOCS-REGISTRY.md` in the same commit.
8. Agent instruction files (`AGENTS.md`, `.agent/**`) are code: change them with a commit that
   says why, and never let two of them give conflicting rules (PROGRAM.md wins for this program).
